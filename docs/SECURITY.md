# 권한 및 사이버보안

- 프로젝트명: IM-BANK
- 최종 수정일: 2026-11-08
- 상태: draft

이 서비스는 민감정보를 찾아 주는 서비스이므로, **서비스 자체가 민감정보를 새로 노출하지 않는 것**을 가장 중요한 원칙으로 둡니다. 데이터 구조는 [데이터베이스 구성](./DATABASE.md), 업무 규칙은 [도메인 정의](./DOMAIN.md)를 따릅니다.

## 1. 역할과 권한 매트릭스 (RBAC)

| 역할 | 코드 | 만드는 방법 | 설명 |
|---|---|---|---|
| 점검 담당자 | `INSPECTOR` | 회원가입, 시드 스크립트 | 문서를 올리고 자기 결과를 봄 |
| 검토자 | `REVIEWER` | 시드 스크립트, 관리자의 역할 변경 | 사람 검토가 필요한 문서를 확인하고 결정을 기록 |
| 관리자 | `ADMIN` | 시드 스크립트만 | 계정과 감사 기록 관리, 점검 담당자·검토자의 기능 전부, 모든 분석의 열람·삭제 (2026-11-08 사용자 결정) |

| 기능 | 비로그인 | `INSPECTOR` | `REVIEWER` | `ADMIN` |
|---|---|---|---|---|
| 회원가입, 로그인 | O | - | - | - |
| 문서 올리기 | X | O | O | O |
| 자기 분석 목록·결과·원본 보기 | X | O | O | O |
| 다른 사람 분석 결과·원본 보기 | X | X | O (검토 대기 또는 검토한 문서) | O (전체) |
| 원문 보기 (사유 필수) | X | 자기 분석만 | 볼 수 있는 분석 | O (전체) |
| 분석 삭제, 다시 실행 | X | 자기 분석만 | 자기 분석만 | O (전체) |
| 검토 대기열, 검토 기록 | X | X | O (자기 분석 제외) | O (자기 분석 제외) |
| 계정 목록, 역할·상태 변경 | X | X | X | O (자기 역할은 변경 불가) |
| 감사 기록 조회 | X | X | X | O |
| 분석 메타데이터(ID, 상태, 등급, 시각) | X | 자기 것 | 볼 수 있는 분석 | O (전체, 파일 이름 포함) |

> ⚠️ 가정: 검토자가 모든 분석이 아니라 "검토 대기 중이거나 자기가 검토한 문서"만 볼 수 있게 했습니다. 최소 권한 원칙 때문입니다. 시연에서 검토자가 전체 문서를 봐야 하면 범위를 넓힙니다.

## 2. 인증 방식

- **세션 쿠키 방식**입니다. React 화면과 API가 같은 출처에서 제공되므로 JWT를 브라우저에 저장할 필요가 없습니다. 토큰이 `localStorage`에 남아 XSS로 탈취되는 위험도 없습니다.
- 세션 쿠키 설정: `HttpOnly`, `SameSite=Lax`, 배포 시 `Secure`(`APP_COOKIE_SECURE=true`), 이름은 `DOCGUARD_SESSION`.
- 세션 유효 시간: 마지막 요청 후 30분. 로그인하면 세션 ID를 새로 발급합니다(세션 고정 공격 방지).
- **CSRF:** Spring Security `CookieCsrfTokenRepository`로 `XSRF-TOKEN` 쿠키를 주고, 화면은 상태를 바꾸는 요청마다 `X-XSRF-TOKEN` 헤더로 보냅니다.
- **비밀번호:** BCrypt(cost 12). 10자 이상이며 영문·숫자를 모두 포함해야 합니다. 이메일과 같은 비밀번호는 거부합니다.
- **로그인 실패:** 5회 연속 실패하면 15분 잠급니다. 오류 문구는 계정이 있든 없든 같게 해서 계정 존재 여부를 알리지 않습니다.
- **미리 만드는 계정:** `scripts/seed-accounts`가 점검 담당자·검토자·관리자 계정을 만들고, 비밀번호는 무작위로 생성해 로컬 파일 `.local/accounts.txt`에만 적습니다. 마이그레이션이나 코드에 비밀번호를 두지 않습니다.
- 회원가입으로는 항상 `INSPECTOR`만 만들어집니다. 요청 본문에 `role`이 있어도 무시합니다.

> ⚠️ 가정: 이메일 인증은 하지 않습니다. 로컬 시연용이기 때문입니다. 공개 배포에서는 회원가입을 닫고(`APP_SIGNUP_ENABLED=false`, 2026-11-08 사용자 결정) 미리 만든 계정만 씁니다.

## 3. 인가 체크 지점

| 계층 | 확인 내용 |
|---|---|
| `SecurityFilterChain` | `/api/auth/**` 일부만 비로그인 허용, `/api/admin/**`은 `ADMIN`, `/api/reviews/**`는 `REVIEWER`·`ADMIN`, 나머지 `/api/**`는 로그인 필요, `/actuator/**`는 `health`만 공개 |
| 서비스 메서드 | 분석 조회·원문 보기·삭제마다 `AnalysisAccessPolicy`로 "소유자인가, 검토 대상인가"를 확인. 컨트롤러가 아닌 서비스에서 확인해 우회 경로를 막음 |
| 저장소 조회 | 목록 조회 쿼리에 항상 `owner_id = :currentUser` 또는 검토 범위 조건을 넣음 |
| 응답 | 접근 권한이 없는 분석은 403이 아니라 **404**로 응답해 존재 여부를 숨김 |
| 화면 | 메뉴와 버튼을 역할에 따라 숨기지만, 이것은 편의 기능일 뿐 보안 경계가 아님 |

권한 테스트는 역할 4가지(비로그인 포함) × 주요 API 전부를 표 형태로 작성합니다(`AuthorizationMatrixTest`).

## 4. 입력 검증과 OWASP Top 10 대응

| 위험 | 대응 |
|---|---|
| A01 접근 통제 실패 | 3장의 서비스 계층 확인, 404 응답, 권한 표 테스트. 분석 ID는 UUID라 추측하기 어려움 |
| A02 암호화 실패 | 원본 파일과 분석 결과, 파일 이름을 AES-256-GCM으로 저장. 배포 시 HTTPS만 허용 |
| A03 인젝션 | JPA 파라미터 바인딩만 사용, 문자열로 쿼리를 만들지 않음. 업로드 파일 이름은 저장 경로에 쓰지 않고 무작위 이름 사용 |
| A04 안전하지 않은 설계 | 판정은 Studio만, 원문 보기는 사유·감사 필수, 관리자의 다른 사람 문서 열람·삭제도 감사 기록에 남김 |
| A05 보안 설정 오류 | actuator는 `health`만 공개, 오류 응답에 스택 추적을 넣지 않음, CORS는 개발용 출처(5173)만 허용 |
| A06 취약한 구성요소 | Gradle·npm 의존성 버전 고정, `npm audit`와 Dependabot(저장소 생성 후) |
| A07 인증 실패 | 2장의 비밀번호 정책, 로그인 잠금, 세션 재발급 |
| A08 무결성 실패 | Studio 응답은 형식 검증 후 사용, 읽지 못하면 `UNKNOWN`으로 처리하고 추측하지 않음 |
| A09 로깅·모니터링 실패 | 7장의 감사 기록, 요청 ID 로그 |
| A10 SSRF | 서버가 호출하는 외부 주소는 `UPSTAGE_BASE_URL` 하나뿐이며, 사용자가 주소를 넣을 수 없음 |

**업로드 검증:**
- 크기와 쪽수는 제한하지 않습니다(2026-11-08 사용자 결정, 실제 문서가 20쪽을 넘는 경우가 많음). Studio 한도(500MB, 1,000쪽)를 넘으면 Studio 단계에서 실패합니다. 서버는 파일을 메모리에 올려 처리하므로, 배포할 때 JVM 힙을 큰 파일에 맞춰 잡고 앞단 프록시의 요청 크기 제한도 확인합니다.
- 크기를 제한하지 않으므로 로그인하지 않은 요청의 본문이 서버에 저장되면 안 됩니다. 업로드 주소 외의 multipart 는 `MultipartGuardFilter`가 본문을 읽기 전에 거절하고, 업로드의 CSRF 토큰은 헤더로만 받습니다(파라미터를 읽으면 Tomcat 이 본문 전체를 디스크에 먼저 저장함). 운영 앞단(Caddy)은 업로드 주소 외의 요청 본문을 1MB 로 제한합니다. 로그인한 사용자의 업로드는 제한이 없으므로 계정 관리가 곧 방어선입니다.
- 형식은 파일 앞부분 시그니처(`%PDF-`, JPEG `FF D8 FF`, PNG `89 50 4E 47`)로 확인하고, `Content-Type`과 확장자는 참고만 합니다.
- 암호가 걸린 PDF는 거부합니다.
- 원본 파일 이름은 화면 표시용으로만 암호화해 저장합니다.

**화면 출력:**
- React 기본 이스케이프를 쓰고, 보고서 본문을 HTML로 넣지 않습니다(`dangerouslySetInnerHTML` 금지).
- 【†n】은 문자열을 파싱해 링크 컴포넌트로 바꿉니다.
- 응답 헤더: `Content-Security-Policy: default-src 'self'; img-src 'self' blob: data:; worker-src 'self' blob:`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`.
- 원본 파일과 결과 응답에는 `Cache-Control: no-store`를 붙입니다.

## 5. 비밀 정보 관리

| 비밀 | 보관 위치 | 규칙 |
|---|---|---|
| `UPSTAGE_API_KEY` | 로컬 `.env` (사용자가 입력) | 저장소, 로그, 화면, 채팅에 남기지 않음. 브라우저로 보내지 않음 |
| `APP_ENCRYPTION_KEY` | 로컬 `.env` (`scripts/create-env`가 생성) | 잃어버리면 저장된 결과를 복호화할 수 없음. 바꿀 때는 `key_version`을 올림 |
| `DB_PASSWORD` | 로컬 `.env` (스크립트가 생성) | Docker Compose도 같은 `.env`를 읽음 |
| 미리 만든 계정 비밀번호 | `.local/accounts.txt` | 시드 스크립트가 생성 |

- `.env`, `.local/`, `storage/`는 `.gitignore`에 넣습니다. `.env.example`에는 변수 이름만 두고 값은 비웁니다.
- 비밀 값 자리에 임시 값(`changeme` 등)도 넣지 않습니다. 값은 스크립트로 만듭니다.
- Project ID와 Agent ID는 비밀은 아니지만, 저장소 파일에는 적지 않고 환경 변수로만 넘깁니다.

## 6. 개인정보 처리와 보관 기간

| 데이터 | 보관 기간 | 삭제 방법 |
|---|---|---|
| Studio에 올린 파일 | 작업이 끝날 때까지 | 완료·실패 직후 `DELETE /v2/files/{id}`. 실패하면 정리 작업이 다시 시도 |
| 서버의 원본 파일, 분석 결과, 발견 항목 | 7일 (`APP_RETENTION_HOURS=168`) | 매시간 정리 작업이 삭제, 상태를 `PURGED`로 변경 |
| 분석 요약 (등급, 상태, 시각) | 계정이 있는 동안 | 계정 비활성화 후 TBD |
| 감사 기록 | 1년 | 매일 정리 작업 |
| 계정 정보 | 비활성화 후 TBD | |

- 처리하는 문서는 대회가 제공한 **합성 문서**뿐이며, 실제 고객 문서는 올리지 않는다고 가입 화면에 안내합니다.
- Studio(Upstage)로 문서를 보내는 것은 외부 처리 위탁에 해당합니다. 가입 화면의 안내에 이 사실을 적습니다.
- 원문값은 서버 응답에서 기본으로 빠지고, `POST /api/analyses/{id}/reveal`로만 받을 수 있습니다.
- 결과 내려받기(`GET /api/analyses/{id}/export`)는 화면과 같은 표시값과 보고서 문장만 담고 원문값을 넣지 않습니다. 파일 이름은 응답 헤더에 넣지 않습니다.
- 가린 PDF는 원본 위에 상자를 얹지 않고 쪽을 이미지로 바꿔 칠하므로 글자 층, 메타데이터, 첨부가 남지 않습니다. 값 위치 없이 영역만 있는 항목은 영역 전체를 칠하고, 위치를 모르는 항목은 건수를 화면에 알립니다. AI가 찾지 못한 정보는 지워지지 않으므로 공유 전에 사람이 확인해야 합니다. 사용자당 분당 10회, 서버 전체 동시 2건으로 제한합니다.
- 인증정보의 비밀 값은 워크플로가 원문값에 `보호값생략`으로 적도록 지시합니다. AI 지시이므로 항상 지켜진다고 보장할 수 없고 원문 근거에는 같은 규칙이 없어, 실제 값이 남으면 암호화 저장되고 원문 보기로 열람될 수 있습니다.

## 7. 로깅과 감사 추적

### 애플리케이션 로그

- 모든 요청에 요청 ID(`X-Request-Id`)를 붙이고 로그에 함께 적습니다.
- **로그에 남기지 않는 것:** 원문값, 원문 근거, 보고서 본문, 파일 이름, 비밀번호, 세션 ID, API 키, Studio 응답 본문.
- **로그에 남기는 것:** 분석 ID, Studio 작업 ID, 상태 전이, 오류 코드, 걸린 시간, HTTP 상태 코드.
- Studio 오류 응답은 `code` 값만 남깁니다(메시지에 파일 정보가 들어갈 수 있으므로).
- 단위 테스트로 대표 로그 메시지에 원문값이 섞이지 않는지 확인합니다.

### 감사 기록 (`audit_logs`)

| 행동 | 기록 시점 |
|---|---|
| `LOGIN_SUCCESS`, `LOGIN_FAILURE`, `LOGOUT`, `ACCOUNT_LOCKED` | 인증 |
| `SIGNUP` | 회원가입 |
| `ANALYSIS_CREATED`, `ANALYSIS_DELETED`, `ANALYSIS_PURGED` | 분석 생성·삭제·정리 |
| `RAW_VALUE_REVEALED` | 원문 보기 (사유 포함) |
| `ORIGINAL_FILE_VIEWED` | 원본 파일을 처음 연 시각 (세션마다 한 번) |
| `RESULT_EXPORTED` | 보고서·결과·가린 PDF를 내려받은 시각과 형식, PDF는 가리지 못한 건수 (내려받을 때마다) |
| `REVIEW_RECORDED` | 검토 결정 |
| `USER_ROLE_CHANGED`, `USER_STATUS_CHANGED` | 관리자 행동 (이전 값과 새 값) |

감사 기록은 추가만 하고 수정·삭제 API를 두지 않습니다.

## 8. 속도 제한과 남용 방지

| 대상 | 제한 | 초과 시 |
|---|---|---|
| 로그인 | 계정당 5회 연속 실패 시 15분 잠금, IP당 분당 20회 | 429 또는 잠금 안내 |
| 회원가입 | IP당 시간당 10회 | 429 |
| 분석 생성 | 건수 제한 없음(2026-11-08 사용자 결정). 아래 "그 밖의 API" 제한만 적용 | 429 |
| 원문 보기 | 사용자당 분당 30회 | 429 |
| 그 밖의 API | 사용자당 분당 300회 | 429 |

- 제한은 서버 메모리(Bucket4j 또는 직접 구현)로 시작합니다. 서버가 한 대이므로 충분합니다. 여러 대로 늘리면 DB나 Redis로 옮깁니다.
- Studio 429는 8장이 아니라 [아키텍처](./ARCHITECTURE.md) 8장의 재시도 규칙을 따릅니다.
